## 1. Purpose

Turn the architect's inputs into a validated, generation-ready bundle:

1. **Program**: `programme.xlsx` (French headers) → `Program` (contract), with a complete validation
   report. Any error **blocks** generation.
2. **Site**: `site.yaml` (polygon, or a closed polyline in a DXF) → `SiteSpec` (contract) → integer
   **module footprint** on the planning grid (0.10 m by default).
3. **Feasibility pre-check**: does the program fit the footprint? If not, say how many m² are missing.
4. **Template**: ship `programme_template.xlsx` with French headers and drop-down lists from the taxonomy.

## 4. Excel program format (`excel.py`)

- Workbook sheet named **`Programme`** (first sheet if absent, with warning `W_SHEET_NAME`).
  Row 1 = headers; data from row 2. Fully empty rows are skipped. A row whose `ID` starts with `#` is a comment, skipped.
- **Header matching** is canonical: accents, case, extra spaces and the suffix `(m²)`/`(m)` ignored
  (`"surface (m2)"` matches `Surface (m²)`). Unknown columns → warning `W_UNKNOWN_COLUMN`. A missing
  required column → error `E_MISSING_COLUMN` and no row is parsed.

| Col | Header (exact text in template) | Req. | → `RoomSpec` field | Accepted values |
|---|---|---|---|---|
| A | `ID` | yes | `id` | `^[A-Za-z0-9_-]{1,32}$` |
| B | `Nom` | yes | `name` | non-empty text |
| C | `Type` | yes | `type` | taxonomy key, `label_fr`, or any synonym whose `normalize_label` rule is **exact**; category must be ROOM or VERTICAL |
| D | `Surface (m²)` | yes | `target_area_m2` | number > 0 and ≤ 10 000; text with `,` or `.` decimal accepted (`"12,5"`) |
| E | `Quantité` | no (1) | `quantity` | integer 1–500 (`3.0` accepted, `3.5` not) |
| F | `Zone` | no | `macro_zone` | `Public`, `Administratif`, `Services` (canonical match; also the enum names); blank → type's `default_macro_zone` (warning `W_ZONE_DEFAULTED`) |
| G | `Façade` | no (Non) | `needs_facade` | `Oui/Non`, `O/N`, `X`/blank, `1/0`, `Vrai/Faux`, `True/False` |
| H–K | `Orientation N`, `Orientation E`, `Orientation S`, `Orientation O` | no | `orientation_override` | numbers in [−1, 1]; all blank → `None`; if any is filled, blanks count as 0.0. `O` (Ouest) → `Bearing.W` |
| L | `Largeur min (m)` | no | `min_width_m` | number > 0 |
| M | `Adjacent à` | no | `adjacent_to` | room IDs separated by `,` or `;` (spaces trimmed) |
| N | `Éviter` | no | `avoid` | same |
| O | `Niveau` | no (0) | `floor` | 0 only in v1 |
| P | `Remarques` | no | — | ignored |

- **Errors are collected, never raised one at a time**: every row and column is checked and all
  issues are returned. Each `Issue` = `code`, `severity` (`error`/`warning`), `row` (Excel row number,
  1-based, or `None`), `column` (header text or `None`), `message` (French, one sentence), `value` (repr of the cell, ≤ 80 chars).
- **Error codes (frozen list)**: `E_MISSING_COLUMN`, `E_NO_ROOMS`, `E_EMPTY_ID`, `E_BAD_ID`, `E_DUP_ID`,
  `E_EMPTY_NAME`, `E_UNKNOWN_TYPE` (message suggests the closest type when `normalize_label` finds a
  *prefix* match), `E_FORBIDDEN_TYPE` (circulation / special), `E_AREA`, `E_QUANTITY`, `E_ZONE`,
  `E_FACADE`, `E_ORIENTATION`, `E_MIN_WIDTH`, `E_REF_UNKNOWN`, `E_SELF_REF`, `E_REQ_AVOID_CONFLICT`
  (A requires B and B avoids A, or same pair in both columns), `E_FLOOR`, `E_ROOM_INFEASIBLE` (§6),
  `E_TYPE_NOT_IN_RULEBOOK`, `E_NOT_FEASIBLE`, `E_FACADE_INSUFFICIENT`, site codes in §5, and (added at review,
  2026-11-07) `E_FILE_UNREADABLE`, `E_SITE_SCHEMA`, `E_RULEBOOK_INVALID`.
  Warning codes: `W_SHEET_NAME`, `W_UNKNOWN_COLUMN`, `W_ZONE_DEFAULTED`.
- `read_program(path) -> tuple[Program | None, ProgramReport]`: `Program` is `None` iff the report has errors.
  The `Program` is built through the contract models (so contract validation also applies; any contract
  `ValidationError` that slips through is converted to issues, never raised).

## 5. Site (`site.yaml`, `site.py`)

```yaml
# Either an inline polygon (metres, site drawing axes, +y up):
footprint: [[0, 0], [24, 0], [24, 18], [0, 18]]
# …or a closed polyline from a DXF file (path relative to the YAML file):
footprint_dxf: {path: emprise.dxf, layer: EMPRISE, units: null}   # units: null → $INSUNITS; else "mm" | "cm" | "m"
north_angle_deg: 0          # clockwise from drawing +y to true north
access_edge: 0              # index of the footprint edge (vertex i → i+1, after orientation to CCW) with the main access
core_hint: null             # optional [x, y] in metres
```

- Exactly one of `footprint` / `footprint_dxf`. Unknown keys → error.
- DXF: exactly one closed `LWPOLYLINE` or `POLYLINE` on that layer in model space (0 or > 1 → `E_SITE_DXF`).
  Unit from `units`, else `$INSUNITS` (4 = mm, 5 = cm, 6 = m); unset/other → `E_SITE_UNITS`. A `.dwg` path → `E_SITE_DWG`
  ("convert to DXF; DWG sites arrive with Ticket 1.2").
- Normalise: coordinates rounded to 1 mm; drop consecutive duplicates and collinear vertices; orient CCW;
  rotate the vertex list so it starts at the lowest-then-leftmost vertex (min y, then min x). The input
  `access_edge` index refers to the **input** order and is remapped to the normalised order (an input edge
  merged by collinear removal maps to the merged edge).
- v1 constraints: simple polygon, **rectilinear in drawing axes** (every edge axis-parallel after mm rounding),
  area > 0. Violations → `E_SITE_INVALID`, `E_SITE_NOT_ORTHOGONAL` (message: rotate the drawing so walls are
  axis-parallel and express the rotation in `north_angle_deg`).
- Result: `SiteSpec` (contract) in metres.

**Metric → module footprint** (`to_module_footprint(site, grid) -> ModuleFootprint`):
- Grid origin = (min x, min y) of the footprint. Relative coordinates converted with `units.m_to_modules`.
- **Inward snapping** by edge direction (polygon is CCW, interior on the left): an edge running +x takes
  `CEIL` for its y; −x → `FLOOR` for y; +y → `FLOOR` for x; −y → `CEIL` for x. Each vertex takes its x from
  its vertical edge and its y from its horizontal edge.
- Then drop collinear vertices; the result must be a valid `ModulePolygon` (contract) with area > 0, else
  `E_SITE_TOO_SMALL`. `access_edge` is carried to the module edge that is the snapped image of the
  original edge; if that edge vanished → `E_SITE_ACCESS_EDGE`.
- `ModuleFootprint` = `polygon: ModulePolygon`, `origin_m: Point2`, `access_edge: int`,
  `sliver_loss_m2: float` (metric area − module area, ≥ 0, exact via mm²).

## 6. Feasibility (`feasibility.py`)

All arithmetic exact (int mm² / `Decimal`), using `AleConfig` values:

1. **Rulebook coverage**: every program type present in `Rulebook.types` → else `E_TYPE_NOT_IN_RULEBOOK` (one issue per missing type).
2. **Per-room buildability**: for each `RoomSpec`, band = rulebook `aspect` [p10, p90] intersected with
   [1.0, `shape.aspect_max`]; `min_short = ceil(min_width_m / module)` (1 if absent);
   `best_buildable_rect(target, grid, band…, min_short_side_modules=min_short)`. If `None`, retry with band
   [1.0, `shape.aspect_max`]; if still `None` → `E_ROOM_INFEASIBLE` (row of that room). The overshoot of the
   chosen rectangle (≥ 0) is the room's expected overshoot.
3. **Global fit**: `required = Σ net × (1 + circulation.ratio) + Σ expected overshoot` (net and overshoot
   counted per instance); `available = module footprint area × site.max_fill`. `required > available` →
   `E_NOT_FEASIBLE`, message `"Programme trop grand : il manque X m² (requis R m², disponible D m²)."`
   with X = required − available rounded **up** to 0.01 m².
4. **Façade**: `Σ facade.min_facade_len_m` over `needs_facade` instances > footprint perimeter (module
   polygon, metres) → `E_FACADE_INSUFFICIENT`.
5. `FeasibilityReport` = `net_m2`, `circulation_m2`, `overshoot_m2`, `required_m2`, `available_m2`,
   `footprint_m2`, `fill_ratio` (= required / footprint), `facade_required_m`, `perimeter_m`, `per_room`
   (spec_id → chosen `(short, long)` modules and overshoot), `issues`.

## 7. `prepare_input` (public API, `prepare.py`)

```python
class PreparedInput(BaseModel, frozen=True):      # in models.py; extra="forbid"
    program: Program
    instances: tuple[tuple[str, RoomSpec], ...]  # Program.instances()
    site: SiteSpec
    footprint: ModuleFootprint
    grid: GridSpec
    rulebook_version: str
    feasibility: FeasibilityReport
    warnings: tuple[Issue, ...]

class InputError(Exception):                     # carries every issue found
    issues: tuple[Issue, ...]

def prepare_input(program_path: Path, site_path: Path, rulebook_path: Path,
                  config: AleConfig) -> PreparedInput     # raises InputError if any error
```
Order: read program, site and rulebook **all** (collect issues from all three), then feasibility if the
three parsed. Same inputs → `canonical_json(prepared)` byte-identical.

## 8. Template (`template.py`)

`python -m ale.program.template OUT.xlsx` writes:
- Sheet `Programme`: the 16 headers of §4 in row 1 (bold, frozen pane, widths set), data validation drop-downs
  on rows 2–500: `Type` (list = `label_fr` of the 72 ROOM/VERTICAL types, from a hidden sheet `Listes`),
  `Zone` (`Public, Administratif, Services`), `Façade` (`Oui, Non`); numeric validation on `Surface` (> 0) and `Quantité` (integer ≥ 1).
- Sheet `Exemple`: the 7 rows of fixture P8 (`program_08.yaml`) in the same columns, types as `label_fr`.
- Sheet `Aide`: one row per column (header, required?, accepted values) in French — the table of §4.
- Hidden sheet `Listes`.
The committed `src/ale/templates/programme_template.xlsx` must be regenerated content-equal by the script
(tests compare cell values and validations, not bytes — xlsx zips carry timestamps).

## 9. CLI (`ale program …`)

```
ale program template --out PATH                          # writes the template; refuses to overwrite unless --force
ale program check --program X.xlsx --site site.yaml --rulebook R.yaml [--workspace WS] [--json]
```
`check` loads `AleConfig` from `--workspace` if given, else defaults; prints issues grouped by severity
(French messages, Excel row/column) and the feasibility summary; `--json` prints `{"ok", "issues", "feasibility"}`.
Exit 0 if no error, 1 if errors, 4 for unreadable config/workspace, 2 usage. `ale generate` stays a stub.

## 10. Out of scope

Graph building, slicing trees, geometry, optimisation, export (3.2–3.5); DWG sites; non-rectilinear or multi-polygon footprints; multi-storey.
